# 技術決策紀錄

每個重要決定一條：日期、決定、理由、代價。推翻舊決定時新增一條，不刪舊的。

## 2026-10-08　用 TypeScript monorepo，套件不另外建置

- **決定**：所有程式用 TypeScript；`packages/*` 直接匯出 `src/index.ts`，由 Vite 與 tsx 直接執行。
- **理由**：Claude 在這個組合上最能「自己寫、自己跑、自己驗證」；網頁版、批次腳本、資料管線共用同一份程式。
- **代價**：效能敏感的部分以後可能要改用 Rust 或 C++ 編成 WebAssembly。

## 2026-10-08　模擬與畫面分離，結果可重現

- **決定**：`sim-core` 不碰畫面；只用自己的亂數；tick 順序固定。
- **理由**：可以無畫面批次調平衡、存檔重播，也為之後的商用版（數位孿生）保留同一個核心。
- **代價**：畫面要的東西都得經過 snapshot，不能直接讀模擬內部。

## 2026-10-08　免費試玩版以高雄市為舞台

- **理由**：範圍適中（38 區），有海、平原、山區，地形變化完整。
- **代價**：數值與鏡頭先只針對高雄調整；擴到其他縣市時要再檢查。

## 2026-10-09　資料管線改用 Node（取代 Python 版）

- **決定**：自己寫 Shapefile/DBF 讀取與 TWD97 轉換（`packages/geo`），不用 GeoPandas。
- **理由**：使用者只需要安裝 Node；Windows 上安裝 GeoPandas 容易出問題。
- **代價**：複雜的空間運算（例如多邊形聯集）要自己寫或另外找套件。

## 2026-10-09　地圖改用 MapLibre GL（取代 three.js 手刻版）

- **決定**：用 MapLibre GL v5 畫地圖：OSM 向量底圖 + DEM 地形 + 山體陰影 + 3D 建築。
- **理由**：使用者的目標畫面是有真實地形的 3D 地景；河流、海岸、湖泊、山、建築都是 OSM 向量資料內建，不必自己做。three.js 版的浮空台座與連線不符合期待。
- **代價**：特殊 3D 效果（例如爆炸、粒子）較難做；需要時可用 MapLibre 的 custom layer 混入 three.js。

## 2026-10-09　底圖用 OpenFreeMap

- **理由**：免費、免金鑰、允許商用，可完整自架（階段 4 會自架）。
- **代價**：公共服務沒有服務保證；樣式要自己維護（階段 1.1）。

## 2026-10-09　公開 repo、GitHub Pages 線上版、GoatCounter 統計

- **決定**：repo 維持公開；推送到 `main` 自動部署到 GitHub Pages；線上版用 GoatCounter 統計瀏覽數。私人文件（`*.docx`）不進版控。
- **理由**：使用者在筆電上透過雲端開發，沒有本機開發環境，開網址就能看畫面最方便；公開 repo 才能免費用 Pages。GoatCounter 免費、不用 cookie，不需要同意視窗。
- **代價**：程式碼與打包內容任何人都看得到，不能放金鑰；想看新改動要先合併到 `main`。設計文件 .docx 曾誤推上公開 repo，已改寫歷史移除。

## 2026-10-09　地景風格走插畫風

- **決定**：地景走插畫風：柔和、低彩度的色塊，地形層次清楚，少用寫實紋理；不使用衛星影像。
- **理由**：截圖要能直接當宣傳圖，插畫風較有遊戲感，也比寫實風更容易在一般筆電上維持好看與流暢。
- **代價**：配色要自己設計與維護（階段 1.1 起）；與真實外觀有落差，需靠區名、地標、等高線維持辨識度。
- **附註**：文件與程式中不提及其他作品名稱作為參考對象，風格以本專案自己的描述為準。

## 2026-10-10　活動斷層依官方分布圖數化

- **決定**：找不到活動斷層的向量檔（SHP／KML），改用經濟部地質調查及礦業管理中心「臺灣活動斷層分布圖（2025）」的圖片，依圖框 TWD97 格線把高雄附近 8 條斷層數化成 `pipeline/data/faults-gsmma-2025.geojson`。
- **理由**：比原本的示意斷層準確很多，而且遊戲只用斷層決定震源位置與各區距離，1–2 公里的誤差影響很小。
- **代價**：位置是約略的，不能當成正式的斷層位置；「關於」頁標明「依圖數化」。日後拿到官方向量檔，用 `--faults` 直接替換即可。

## 2026-10-10　難度穩定：縮小規模隨機範圍，大地震時增派搜救隊

- **問題**：換成真實斷層後，評級幾乎由抽到的地震規模決定（規模 6.5–6.6 全拿 S、7.0 以上全拿 C），跟玩家的決策關係不大。
- **決定**：規模隨機範圍從 ±0.3 縮小為 ±0.15（`magnitudeJitter`）；每 1000 名受威脅者開局多 1 隊搜救隊（`aidTeamsPer1000AtRisk`，大地震時中央與外縣市支援較多）。
- **結果**（greedy 200 場）：S37% A21% B20% C24% → S30% A36% B35% C0%；小震與大震的平均分差距從 24 分縮小到約 14 分。不下指令與亂下指令仍然全拿 D。
- **代價**：每局地震大小的變化變少；若想要更多變化，可改成讓玩家選難度（不同規模）。

## 2026-10-10　玩家可選難度

- **決定**：指揮面板加「難度」：輕度（規模 6.6）、標準（6.8）、嚴重（7.0），定義在 `rules-game` 的 `DIFFICULTIES`，只覆寫地震規模；評級門檻相同，越難越不容易拿高評級。
- **理由**：縮小規模隨機範圍後每局變化變少，改由玩家主動選擇大小地震。
- **批次跑分**（greedy 200 場）：輕度 S96% A4%；標準 S30% A36% B35%；嚴重 A2% B43% C56%。三種難度 idle 都是 D。

## 2026-10-10　遊戲性暫停，改做即時交通

- **決定**：「地震 72 小時」暫停開發（現有功能保留、可玩）；新重點是在 3D 高雄上顯示即時交通（公車、捷運、輕軌、臺鐵、路況），並做管理後台管理資料串接。
- **理由**：使用者希望先把真實、即時的城市資訊做起來；地景已經完成，正適合疊上即時資料。
- **代價**：遊戲的試玩驗收（階段 3）延後；觀景模式工具列的主按鈕改成「即時交通」。

## 2026-10-10　即時交通資料走自己的伺服器，不由網頁直接呼叫 TDX

- **決定**：新增交通資料伺服器 `apps/server`（Node 內建 http，不裝框架）。伺服器保管 TDX 的 Client ID／Secret、定時抓取、轉成統一格式（`packages/traffic`），網頁版只呼叫 `/api/traffic/snapshot`。管理後台 `admin.html` 透過 `/admin/api` 設定，用管理者權杖保護。
- **理由**：TDX 需要金鑰，公開 repo 與 GitHub Pages 上的網頁不能放金鑰；集中由伺服器抓也能控制呼叫次數（TDX 有每秒上限），很多人同時看也只呼叫一次。
- **代價**：要多跑一個伺服器（本機 `npm run server`，或部署到雲端）；沒有伺服器時網頁版只能顯示示範資料。設定檔 `apps/server/data/config.json` 存金鑰，不進版控。

## 2026-10-10　捷運列車位置先用「即將進站」表示

- **決定**：TDX 沒有高雄捷運、輕軌的列車 GPS，只有各站到站時間；第一版把 1 分鐘內到站的列車畫在該站上。臺鐵用列車所在車站。公車有 GPS，直接畫實際位置，兩次更新之間平滑移動。
- **理由**：不需要額外資料就能上線；推估站間位置要用時刻表，留到 T.7。
- **代價**：軌道車輛看起來會「跳站」，不像公車連續移動。

## 2026-10-10　3D 車輛用地圖內建的立體擠出，不另外載入 3D 模型

- **決定**：列車與公車畫成 fill-extrusion 的立體車廂（和 3D 建築同一種圖層），每節車廂分成車身、窗帶、車頂三段，顏色用路線顏色；車廂沿軌道線形排列。拉遠時放大，並把車寬、車高加粗成「微縮模型」比例。
- **理由**：不用加 three.js 或模型檔，打包大小不變、手機也跑得動；和地形、建築的光影一致，點選也沿用同一套機制。
- **代價**：外型是方塊車廂，沒有車頭流線造型與細節；比例刻意誇張，不是真實尺寸。需要更精緻的車型時，再用 custom layer 載入 glTF 模型。

## 2026-10-10　天氣用地圖內建圖層＋一層雨絲畫布

- **決定**：雲畫成 fill-extrusion 的懸空雲團（每團三層疊成低多邊形圓頂），雲影是貼地的半透明多邊形；雨是疊在地圖上方的 2D 畫布（螢幕座標的斜雨絲）；陰天、雨天的色調用同一個 `overcast()` 套到配色、天空、光線。天氣先由使用者手動選（晴、多雲、下雨），不接即時氣象。
- **理由**：和 3D 車輛同樣不加 three.js、不加模型檔與圖片，手機也跑得動；分層的立體雲符合「微縮模型」插畫風。雨絲用畫布比在 3D 場景裡放粒子便宜很多，看起來也夠。即時天氣（中央氣象署 API）需要金鑰，依硬規則 10 要經過伺服器，留待之後。
- **代價**：雲是方塊疊成的，不是柔軟的體積雲；雲朵懸空但都在山頂以上、拉近市區就淡出，不是「浮空台座」。雲影只是依太陽方向平移的平面，不是真正的陰影計算。雨絲是螢幕上的效果，不會因鏡頭角度改變方向。雲影每次更新都要重畫地形貼圖，所以飄移更新頻率刻意放慢（`CLOUDS.frameMs`）。
